# Drone Based Campus Analytics - Dashboard

Final Year Project, Sir Syed University of Engineering & Technology (SSUET).
Module: **Dashboard Development, Integration and Testing**.

A modular Python **Streamlit** web dashboard that runs locally on Windows. It catalogues,
validates and visualises the outputs of the drone survey pipeline: georeferenced orthomosaics,
GIS layers, land-use and green-cover analysis, and 3D campus assets.

> **Data status.** The repository ships with **synthetic demo data only** (`data/demo/`). It is
> generated by a script, labelled `[DEMO]` everywhere in the UI, and is **not** a drone survey
> result: it does not depict real SSUET buildings, land use or vegetation. No accuracy is claimed
> for any result unless it is measured against independent reference data.

---

## 1. Features

| Page | What it does |
|---|---|
| **Overview** | Headline figures (datasets, mapped area, green cover, buildings), a study-area map with legend, land-use chart, and the dataset catalogue with provenance. |
| **Orthomosaic & GIS Map** | Leaflet map with basemap choice, GeoTIFF orthomosaic overlays (opacity control), any vector layers, an optional XYZ tile URL (e.g. WebODM/TiTiler), layer control, legend, measuring tool, coordinates readout. |
| **Land Use** | Area per class in a local UTM projection, optional clipping to a boundary, class filters, map + bar chart + table, CSV export, comparison of two layers (e.g. two survey dates). |
| **Green Cover** | (a) share of green classes from polygons; (b) estimate from the orthomosaic with **ExG / VARI** (RGB) or a single-band index (e.g. NDVI) with an adjustable threshold (Otsu suggestion) and histogram; (c) **validation** against reference points: confusion matrix, overall accuracy, precision, recall, kappa. |
| **Spatial Layers** | Generic explorer for any other result (paths, trees, survey points...): attribute filters, area/length summaries, charts, attribute table, GeoJSON export. |
| **3D Campus Assets** | Extruded buildings from footprint heights (pydeck), mesh viewer for GLB/glTF/OBJ/PLY/STL (model-viewer), point-cloud viewer for PLY/LAS/LAZ (Plotly, subsampled). |
| **Data Manager** | Upload with validation, metadata form (source, capture date, sensor, software, GSD, accuracy statement, licence), preview, save; edit metadata; delete user datasets. |
| **Methodology & Data Status** | Methods, limitations and the data-status policy. |

**Supported formats**

- Vector: GeoJSON (`.geojson`, `.json`), GeoPackage (`.gpkg`), zipped Shapefile (`.zip`), KML (`.kml`), CSV (lat/lon or WKT columns).
- Raster: GeoTIFF / Cloud-Optimised GeoTIFF (`.tif`, `.tiff`), RGB orthomosaic, single-band index, DSM/DTM.
- 3D: `.glb` (recommended), `.gltf`, `.obj`, `.ply`, `.stl`, `.off`, `.las`, `.laz` (needs `lazrs`).

**Validation messages** are shown in three levels: *errors* block saving (no CRS, not georeferenced,
coordinates out of range, missing land-use class field, negative heights, wrong format/size);
*warnings* inform (geometries repaired, unknown classes, overlapping polygons, data far from campus,
no nodata/alpha, small reference sample); *info* lists facts (CRS, feature count, extent, pixel size).

```
│   ├── assets3d.py             # meshes, point clouds, building extrusion
│   └── ui.py                   # shared Streamlit helpers (banners, caching, selectors)
├── data/
│   ├── demo/                   # SYNTHETIC demo data (always treated as demo)
│   └── user/                   # your uploads: vector/, raster/, 3d/ (+ .meta.json sidecars)
├── scripts/
│   └── generate_demo_data.py   # regenerates data/demo
├── tests/                      # pytest suite (unit tests + page smoke tests)
├── .streamlit/config.toml      # upload size limit, theme
├── requirements.txt            # runtime dependencies
├── requirements-dev.txt        # + pytest
└── pytest.ini
```

**Why no database?** The dashboard only has to list a few dozen datasets and their descriptions.
Each dataset keeps its metadata in a JSON *sidecar* file next to it
(`landuse.geojson` → `landuse.geojson.meta.json`), so provenance travels with the data when the
folder is copied between team members, and there is nothing extra to install or back up. Revisit
this only if a concrete need appears (multi-user editing, audit history, thousands of datasets).

## 3. Setup on Windows (step by step)

Prerequisites: **Windows 10/11 (64-bit)** and **Python 3.11 or 3.12 (64-bit)** from
<https://www.python.org/downloads/windows/>. During installation tick **"Add python.exe to PATH"**.
All GIS libraries (GDAL via `rasterio` and `pyogrio`) install as pre-built wheels, so there is
**no need for OSGeo4W, conda or a separate GDAL install**.

Open **PowerShell** (or *Command Prompt*) and run the commands below one at a time.

| # | Command | What it does |
|---|---|---|
| 1 | `py --version` | Checks that Python is installed. It should print `Python 3.11.x` or `3.12.x`. |
| 2 | `cd C:\Users\<you>\Projects\campus-dashboard` | Moves into the project folder (adjust the path). |
| 3 | `py -3.12 -m venv .venv` | Creates an isolated *virtual environment* in `.venv`, so project packages do not clash with other Python projects. (Use `-3.11` if that is your version.) |
| 4 | `.venv\Scripts\Activate.ps1` (PowerShell) or `.venv\Scripts\activate.bat` (cmd) | Activates the environment; your prompt now starts with `(.venv)`. Every `python`/`pip` command after this uses the project environment. |
| 5 | `python -m pip install --upgrade pip` | Updates the installer so it picks the newest pre-built wheels. |
| 6 | `pip install -r requirements-dev.txt` | Installs everything in `requirements.txt` (Streamlit, GeoPandas, rasterio, Folium, Plotly, ...) plus `pytest` for testing. Takes a few minutes the first time. |
| 7 | `python scripts\generate_demo_data.py` | *(Optional)* Regenerates the synthetic demo data in `data\demo\`. It is already included, so you only need this if you deleted it or changed `CAMPUS_CENTER_LATLON`. |

If PowerShell refuses step 4 with *"running scripts is disabled on this system"*, run this once and
then repeat step 4:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

(This allows locally created scripts such as the venv activator to run for your user account only.)

---

## 4. Run the dashboard (localhost)

With the virtual environment active, from the project folder:

```powershell
streamlit run app.py
```

- Streamlit starts a local web server and opens **http://localhost:8501** in your browser.
- Stop the server with **Ctrl + C** in the terminal.
- Use another port if 8501 is busy: `streamlit run app.py --server.port 8502`.
- Next time you only need: `cd` into the folder → activate (step 4) → `streamlit run app.py`.

**Internet access:** the app and your data run entirely on your PC. The browser does load map
libraries (Leaflet), basemap tiles (OpenStreetMap / Esri) and the 3D model viewer script
(Google model-viewer) from public CDNs. Without internet the analysis, charts, tables, point-cloud
viewer and extruded buildings still work; maps lose their background tiles and the GLB viewer
cannot load.

```powershell
python -m pytest            # whole suite (about 10 s)
python -m pytest -v         # verbose: one line per test
python -m pytest tests\test_validation.py   # a single file
```

| File | Covers |
|---|---|
| `test_vector_io.py` | Reading GeoJSON, GPKG, KML, zipped Shapefile (complete/incomplete/corrupt), CSV (lat/lon, WKT, Excel encodings), error messages, metric reprojection. |
| `test_validation.py` | Empty layers, missing CRS, repaired geometries, wrong CRS, far-from-campus, land-use class field/unknown classes/overlaps, building heights, upload extension/size, raster georeferencing, reference labels. |
| `test_analysis.py` | Land-use areas (1 ha squares), clipping, green share, ExG/VARI, Otsu, raster green cover end-to-end, accuracy metrics with known answers. |
| `test_metadata_catalog.py` | Sidecar round-trip, missing/corrupt sidecars, demo flag enforced in `data/demo`, discovery, safe filenames, delete protection for demo data. |
| `test_raster_3d_charts.py` | Raster preview/reprojection, colour ramps, GLB/STL/PLY handling, extrusion, chart demo labels, HTML escaping in map tooltips, XYZ URL validation. |
| `test_app_smoke.py` | Every page renders without an exception (with and without demo data), demo banner behaviour, deleting a dataset through the UI. |

**Manual test checklist** (for the project report):

1. Start the app → Overview shows the *"No project survey data"* notice and the yellow **DEMO** banner.
2. Sidebar → turn off *Include demo data* → pages show "No ... available yet" messages instead of data.
3. Data Manager → upload a GeoJSON without a class column as *Land-use* → red error, Save hidden.
4. Upload a valid land-use layer → warnings/info listed → Save → layer appears on Land Use without a DEMO label.
5. Upload a plain photo (e.g. a drone JPEG saved/renamed as `.tif`) → "The raster is not georeferenced" error.
6. Green Cover → Index tab → move the threshold → green %, histogram line and mask update.
7. Data Manager → Manage → delete your uploaded layer → confirmation message; demo files cannot be deleted.

## 6. Adding real survey data

1. Export from the photogrammetry software (WebODM, Agisoft Metashape, Pix4D):
   - Orthomosaic as **GeoTIFF** with a CRS (e.g. WGS 84 / UTM zone 42N, EPSG:32642), ideally with an
     alpha band or nodata value. Very large mosaics: export a Cloud-Optimised GeoTIFF, or serve tiles
     and paste the XYZ URL on the map page.
   - 3D mesh as **GLB** (decimate to < 80 MB for in-browser display); point cloud as LAS/LAZ or PLY.
2. Digitise / classify land use in QGIS with a `class` attribute using the codes in
   `campus_dashboard/config.py` (`building`, `road`, `parking`, `paved_open`, `bare_soil`,
   `lawn_grass`, `trees_shrubs`, `sports_field`, `water`, `other`). Edit that file if the team
   agrees on different classes or on which classes count as green.
3. Building footprints: add `height_m` (metres) for 3D extrusion.
4. Upload each file in **Data Manager**, fill in the metadata honestly (leave the accuracy statement
   as *"Not validated"* unless you measured it), and save.
5. For a defensible green-cover figure, collect **independent reference points** (`is_green` = 1/0,
   ideally 50+ points spread over all surface types, not used for choosing the threshold) and use the
   *Validation* tab. Report the resulting accuracy with the number of points.

You can also copy files straight into `data/user/vector`, `data/user/raster` or `data/user/3d`;
they appear automatically (with a "provenance unknown" note until you add metadata).

## 7. Configuration

`campus_dashboard/config.py`: campus map centre (approximate, used only for centring maps and the
"far from campus" warning), upload limits, preview/analysis resolution, land-use classes and colours,
basemaps. `.streamlit/config.toml`: browser upload limit (`maxUploadSize`, MB) and theme.

---

## 8. Limitations

- Orthomosaics are displayed and analysed at a decimated resolution (≤ 2048 / 1500 px); full-resolution
  files are never modified.
- Areas are planimetric (2D) in a local UTM zone.
- RGB vegetation indices measure greenness, not plant health; shadows and green surfaces cause errors.
- The dashboard does not measure positional accuracy of orthomosaics (that requires GCP/check-point
  reports from the processing software).
- Demo data is invented and must not appear in the project report as results.

## 9. Later: cloud deployment (not yet)

Once the localhost version is accepted, options include Streamlit Community Cloud (public GitHub repo,
1 GB RAM - too small for large orthomosaics), or a university/VPS server running
`streamlit run app.py --server.address 0.0.0.0` behind a reverse proxy. Before that: decide where
survey data is stored (large files should not go into Git), add authentication if data is not public,
and serve large orthomosaics as tiles (TiTiler / GeoServer) instead of uploading them.

## 10. Troubleshooting

| Problem | Fix |
|---|---|
| `'streamlit' is not recognized` | The virtual environment is not active - repeat setup step 4. |
| `pip` tries to *build* GDAL / rasterio | You are on 32-bit or a very new/old Python. Install 64-bit Python 3.11 or 3.12. |
| Map shows no background | No internet, or the tile server is blocked - data layers still display. |
| 3D model stays on "Loading..." | The model-viewer script needs internet; or convert the model to GLB. |
| Upload limit exceeded | Raise `maxUploadSize` in `.streamlit/config.toml` and `MAX_UPLOAD_MB` in `config.py`. |
| `.laz` cannot be read | `pip install lazrs` (LAZ decompression backend for laspy). |
| File cannot be deleted on Windows | Another program (QGIS, Explorer preview) has it open - close it and retry. |
